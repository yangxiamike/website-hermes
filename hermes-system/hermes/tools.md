# 工具

## 原则

员工和工具分开。

员工负责判断、责任和结果。工具负责执行特定任务。

Kimi K2.6 和 Codex 5.3 不是当前 Hermes 团队的核心员工。它们是 Dex 在网站制作过程中使用的生产工具。

## Dex 工具链

Dex 负责完整的网站制作流水线，可以使用两个主要工具。

## Kimi K2.6

### 角色

Kimi K2.6 是原型生成工具。

### 使用者

Dex

### 适合用于

- 快速生成网站原型
- 初版页面布局
- 视觉方向探索
- HTML/CSS demo 生成
- 初版内容摆放
- 把 Mira 的网站 brief 变成可见草稿

### 规则

Kimi 输出是原型，不是最终交付物。

Dex 必须审核 Kimi 输出，判断哪些保留、哪些修改、哪些废弃。Kimi 原型必须经过工程深化和 QA 后，才能成为正式展示资产。

## Codex 5.3

### 角色

Codex 5.3 是工程深化工具。

### 使用者

Dex

### 适合用于

- 把 Kimi 原型转成生产级网站项目
- 重构原型代码
- 组件化页面布局
- 优化响应式体验
- 添加 SEO metadata
- 实现表单和交互细节
- 优化基础性能
- 维护本地项目文件
- 运行测试并修复问题
- 准备 Git 和部署所需资产

### 规则

Codex 输出是正式工程版本，但仍需要 Dex 自检和 Nora 最终 QA。

Codex 不应独自决定业务定位。它可以提出工程改进建议，但优先级由 Hermes 判断，最终验收由 Nora 负责。

## GitHub

GitHub 是资产维护和版本控制环境，也是 Hermes 自主维护独立站工程健康的主要场所。

Hermes 对独立站项目的 GitHub 远程仓库拥有开发最高权限，可以自主修复问题、更新依赖、维护 CI、提交、推送、合并和部署。

Hermes 的目标是保持项目健康、可构建、可部署。完成 GitHub 维护后，只需要向创始人汇报结果，不需要创始人参与代码 review。

涉及收款账户、生产数据库、仓库删除、所有权转移、真实客户资料公开、预算投入或长期业务承诺时，必须先获得创始人确认。
